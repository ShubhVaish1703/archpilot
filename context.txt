1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
ArchPilot is an AI-assisted System Architecture Visualizer & Evaluation Engine.
It enables engineers and architects to design high-level distributed systems
using an interactive visual drag-and-drop canvas, and will evaluate architectures
for Single Points of Failure (SPOFs), bottlenecks, capacity sizing, scalability
risks, and anti-patterns.

Core Philosophy ("Not a Thin LLM Wrapper"):
- Code computes the deterministic facts:
  * Graph topology (cycles, articulation points / SPOFs, fan-in/fan-out bottlenecks).
  * Capacity sizing heuristics (RPS, storage estimates, compute node counts).
  * Rule-based anti-pattern checks (e.g., Client directly connecting to Database,
    un-cached heavy read databases, synchronous queues).
  * Quantitative architectural scores (Scalability, Reliability, Cost, Security).
- The LLM (Google Gemini) receives computed engine facts and RAG context to:
  * Narrate explanations and actionable remediation steps.
  * Suggest trade-offs and generate architecture variants (Cost-Optimized,
    High-Availability, Low-Latency, Simplified).

  - Custom node components with protocol badges (HTTP, gRPC, WebSocket) and status handles.

Phase 2: Deterministic Computation Engine (`server/src/services/engine/`) (COMPLETED)
  - Two-Phase Pipeline architecture:
    * Phase 1 (`buildGraphProfile`): 3-4 structured passes compute all topological facts
      (articulation points, cycles, connected components, reachability, orphans, degrees)
      into an immutable GraphProfile object.
    * Phase 2 (`runStructuralRules`): 18 structural rules execute in a single read-only pass
      emitting findings without re-traversing the graph.
  - Complete Structural Rules Catalog:
    * Connectivity: TOPO_ORPHAN_NODE, TOPO_DISCONNECTED_SUBGRAPH, TOPO_NO_ENTRY_POINT
    * Flow: TOPO_UNREACHABLE_FROM_ENTRY, TOPO_DEAD_END_SERVER, TOPO_DB_UNREACHABLE, WRONG_FLOW_REVERSED
    * Security: SEC_CLIENT_DIRECT_DB, SEC_NO_AUTH, SEC_DB_NO_FIREWALL
    * Reliability: SPOF_CRITICAL_PATH, REL_CIRCULAR_DEPENDENCY, REL_QUEUE_NO_CONSUMER,
      REL_QUEUE_NO_PUBLISHER, REL_CACHE_WITHOUT_DB
    * Scalability: UNDER_NO_LB_MULTI_SERVER, REL_LB_SINGLE_TARGET, UNNECESSARY_CONNECTION
  - `scoring.js`: Multi-dimensional 1-10 rubric (Security, Reliability, Scalability) with partial scoring.
  - Express API: `POST /api/analyze` connected to frontend "Analyze design" action.
  - Multi-status canvas visualization (Red = SPOF, Amber = Cycle, Purple = Unreachable, Gray dashed = Orphan).

Phase 3: Gemini LLM Integration (`server/src/services/llm/`)
  - Integration with `@google/genai` or official Google Gemini API SDK.
  - Structured prompt assembling graph summary, computed SPOFs, and detected anti-patterns.

Phase 4: Frontend Analysis Review Modal & Real-Time Flow

6. GUIDELINES FOR ANY AI CODING ASSISTANT
--------------------------------------------------------------------------------
1. Frontend is Next.js 16 App Router in TypeScript (.tsx, .ts).
   - Use React 19 hooks and `@xyflow/react` idioms.
   - Do not degrade TypeScript types; use strict type checking.
2. Styling is Tailwind CSS v4.
   - Use standard Tailwind utility classes and modern flex/grid layouts.
3. Separation of Concerns:
   - Keep canvas layout and node components modular (e.g. `src/components/canvas/`,
     `src/components/inspector/`).
   - Keep graph computation logic in pure, testable utility functions.
4. Deterministic Engine Integrity:
   - Never prompt the LLM to hallucinate graph metrics (SPOFs, node counts, cycle detection).
   - The backend graph engine must compute the facts; the LLM explains them.
5. Canvas Performance:
   - When updating nodes or edges, use functional state updates (`setNodes`, `setEdges`)
     to avoid stale closures and excessive re-renders.
